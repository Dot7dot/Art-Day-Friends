# Art Day · 藝術小日曆

每天隨手畫一張，只給今天的朋友看。

**網站：** https://dot7dot.github.io/Art-Day-Friends/

## 它是什麼

Art Day 是一個給藝術家的小日曆：

- **自己註冊帳號**，每天上傳隨手畫的圖（或直接在 App 裡「隨手畫」），也可以寫一段當天的文字記錄。
- **好友機制**：互相加好友後，就能看到對方**今天**畫的圖和文字。
- **只有今天**：好友只看得到當天的畫，看不到以前的。過了午夜就消失。
- **畫留在身邊**：所有的畫都存在你自己的裝置裡，在「日曆」頁一格一格地累積成你的藝術日曆。

## 儲存方式（節省雲端空間）

| | 存在哪裡 | 存多久 |
|---|---|---|
| 你所有的畫（原圖品質，最長邊 2048px） | **本機**：這台裝置瀏覽器的 IndexedDB | 永久（直到你刪除或清除瀏覽器資料） |
| 今天的畫（壓縮副本，最長邊 1280px） | **雲端**共用空間 | 只到今天結束，隔天自動刪除 |
| 今天的文字記錄 | 本機 + 雲端 | 雲端同樣只留到今天結束 |
| 好友在畫上的留言（純文字） | 雲端 + 畫主人的本機快取 | 雲端永久保留（很小），不隨畫刪除 |

雲端每人每天最多放 6 張，所以就算用免費方案，空間也不會越用越多。

隔天的清除有三道保險：

1. 資料庫的安全規則（RLS）會讓「已過期」的畫立刻對好友隱藏。
2. 每次有人打開 App，都會刪掉自己昨天以前的雲端副本，並順手清掉所有人已過期的資料。
3. 若有開啟 pg_cron，資料庫每 30 分鐘也會自動清一次。

> 因為圖片主要存在瀏覽器裡，**清除瀏覽器資料或換手機前，請到「我的」頁面匯出備份**。在「我的」頁面也可以開啟「防止瀏覽器自動清除」。

## 留言

好友可以在彼此**今天**的畫上留言（點開畫就能看到留言串，最多 200 字、純文字）。

- **畫的主人**可以看到、回覆，也能刪除自己畫上的任何留言；留言者可以刪除自己的留言。
- **畫過了今天就不能再留言**，也只有主人與留言者本人看得到舊留言；其他好友只在畫還沒過期時看得到。這些規則由資料庫的 RLS 把關（`drawing_comments`），不只是畫面上的限制。
- **留言會永久保留**：畫的圖片隔天會從雲端刪除，但留言只是很小的文字，不會被清除。你可以在「日曆」頁點選以前的日子，在每張畫下面看到好友當天留下的字；留言也會快取在你的裝置裡（`artday-archive` 的 `comments`，並包含在匯出備份中），離線也看得到。
- 刪除自己今天的畫時，上面的留言也會一起刪除。每人每張畫最多留 30 則。

> **已經在使用雲端模式的話**：更新網站後，請到 Supabase **SQL Editor** 把最新的 [`supabase/schema.sql`](supabase/schema.sql) 整份再執行一次（可重複執行，不會刪掉資料），才會開啟留言功能。在那之前，App 其他功能照常運作，只是留言區會顯示「留言暫時載入不到」。

## 推薦好友

「好友」頁的「好友名單」最下面會顯示「你可能認識」，「今日動態」底部也有精簡版（還沒有好友時，空畫面也會推薦幾位）：

- 先列出**共同好友最多**的人（例如「3 位共同好友」），不夠再用最近加入的人補滿（顯示「新加入」）。
- 不會推薦自己、已經是好友、或雙方任一邊還有待回覆邀請的人。按「略過」就不再顯示那位（記在這台裝置的瀏覽器裡）。
- 雲端版由資料庫函式 `suggest_friends()` 計算，只回傳「共同好友的**數量**」，不會洩漏共同好友是誰或別人的好友名單。

> **已經在使用雲端模式的話**：請到 Supabase **SQL Editor** 把最新的 [`supabase/schema.sql`](supabase/schema.sql) 整份再執行一次（可重複執行），才會開啟推薦好友。在那之前這一區會自動隱藏，其他功能不受影響。

## 首頁、「＋」按鈕與大頭貼

- **首頁就是好友動態**：打開網站（或點左上角的 Art Day）會先看到好友今天畫的圖。底部導覽依序是「好友、日曆、我的」。動態頁沒有重新整理按鈕：每次進來都會載入，切回 App 或分頁時若已超過 1 分鐘也會自動更新。
- **右下角的「＋」**（液態玻璃效果的圓形按鈕）：點開後可以「上傳圖片」或「隨手畫」，圖片會直接加進**今天**，做法和日曆頁的「今天」一樣（存本機、同步雲端、遵守每日雲端上限），完成後的提示可以點「查看」到日曆頁（自動選到今天）。
- **大頭貼**：到「我的」點大頭貼（或「更換大頭貼」）選一張圖，會自動置中裁成正方形、縮成 160×160 的小圖（約 10–20 KB）；也可以「移除大頭貼」。沒有設定時，顯示暱稱的第一個字。好友動態、好友名單、搜尋結果、推薦好友與留言都會顯示大頭貼。

> **已經在使用雲端模式的話**：大頭貼需要資料庫多一個欄位，請到 Supabase **SQL Editor** 把最新的 [`supabase/schema.sql`](supabase/schema.sql) 整份再執行一次（可重複執行，不會刪掉資料）。在那之前 App 其他功能照常運作，只是大頭貼不會顯示，上傳時會提示請管理員更新資料庫。

## 存到手機相簿、安裝到主畫面

網頁沒有任何辦法在背景直接把圖片寫進 iPhone「照片」或 Android「相簿」，所以 Art Day 用瀏覽器允許的做法，每一種最多只需要點一下或按「允許」：

- **存到相簿**：每張畫（大圖視窗、日曆、首頁自己的貼文）都有「存到相簿」。手機上會開啟系統分享表（iPhone 選「儲存影像」就進「照片」；Android 可選相簿／照片／檔案）；電腦或不能分享的瀏覽器會改成下載 JPEG（檔名像 `art-day-2026-11-18-1.jpg`；Android Chrome 的下載相簿通常也看得到）。
- **自動存到手機**（我的 → 存到手機）：開啟後，每次新增畫都會自動下載一份完整畫質的 JPEG（Android Chrome 第一次可能問你是否「允許」自動下載）。iPhone／iPad 不允許自動存進「照片」，所以改成新增後跳出「存到相簿」，點一下開分享表。
- **全部存到相簿**：可選全部或某個月份；手機上每批最多 10 張、每批點一下（「下一批」），並顯示進度；電腦則一張張下載。
- **安裝到主畫面**（我的 → 本機保存）：Android／電腦 Chrome 有「安裝」按鈕；iPhone 請用 Safari 的 分享 → 加入主畫面（按鈕會顯示步驟）。網站附有 `sw.js`（網路優先，更新網站後下次打開就是新版；離線也打得開 App 外殼；不會快取 Supabase 或任何其他網域的請求）。改了 `sw.js` 的快取版本號 `VERSION` 可清掉舊快取。
- **保護本機資料**：第一次新增畫後會自動請瀏覽器「不要自動清除」（`navigator.storage.persist()`，「我的」仍有手動按鈕）。⚠️ iPhone／iPad 的 Safari 會在一段時間沒使用後，清掉**沒有加入主畫面**的網站資料；建議安裝到主畫面，並用「存到相簿」或匯出備份另外留一份。

## 推薦貼文（選擇加入）

首頁會在好友貼文之後（好友貼文超過 3 則時，放在第 3 則之後）顯示「推薦」貼文：來自**不是好友、而且自己同意公開**的人今天的畫，可以直接「加好友」或「不感興趣」（只存在這台裝置）。

- **預設關閉**：`profiles.share_public` 預設 `false`。新註冊時第二步有勾選框（預設勾選，可取消）；已有帳號會在首頁看到一次性的詢問卡片；隨時可到 我的 → 推薦 開關。
- **看得到什麼**：只有「今天」的畫與文字，過了午夜就消失；對方只能看，**不能留言**（留言規則仍然只限好友）。
- **已經在使用雲端模式的話**：請把最新的 [`supabase/schema.sql`](supabase/schema.sql) 在 SQL Editor 整份再執行一次（可重複執行）。在那之前，推薦貼文、「推薦」開關與詢問卡片會自動隱藏，其他功能不受影響。
- 示範模式：示範畫家預設都公開，`@nana_paint`、`@kai_ink` 每天都會畫、也不會自動成為好友，所以一定看得到推薦。

## 許願池、回覆與通知、注意事項、戳好友

> 已經建立過 Supabase 專案的人：這幾個功能需要**重新執行一次整份 `supabase/schema.sql`**（可重複執行，不會刪掉資料）。沒更新時，App 不會壞掉：許願池會顯示「還沒開啟」、戳好友的按鈕與通知區會自動隱藏、留言照常可用。

- **許願池**：首頁的「許願池」按鈕。使用者可以寫下想要的新功能（最多 500 字，24 小時內最多 10 個），只看得到自己許過的願望。
  - **網站管理員怎麼看所有願望**：Supabase Dashboard → Table Editor → `wishes`；或到 SQL Editor 執行
    `select * from wishes_with_author order by created_at desc;`（附上許願的使用者 ID 與暱稱）。這個檢視只有 Dashboard／service role 讀得到，App 的使用者完全讀不到。
- **回覆與通知**：在畫的留言區，別人的留言旁有「回覆」。回覆仍是一般留言（資料表 `drawing_comments.reply_to`，必須是同一張畫上的留言），列表維持依時間排序、不分層。被回覆的人會收到通知（回覆自己不通知）；通知放在「我的」最上面，「我的」分頁圖示上的數字是沒讀的通知數（約每分鐘更新一次）。打開「我的」就會把通知標成已讀；點通知可以直接開啟那張畫（畫已經看不到時會提示）。通知資料表 `notifications` 使用者只能讀、標已讀、刪自己的，**不能自己新增**，只由資料庫的觸發器與 `poke_friend()` 建立；超過 30 天的通知會自動清除（留言永遠不會被清除）。
- **注意事項**：首頁最上方黑底白字的說明（文字在 `js/app.js` 的 `noticeHtml()`）。
- **戳好友**：首頁右下角、「＋」上方的小按鈕。列出好友（今天已經畫的會標「今天畫了」），按「戳一下」就會通知對方「叫你快去畫圖」；同一位好友 12 小時內只能戳一次（資料庫函式 `poke_friend`，只有好友能戳）。被戳的人在「我的」最上面看到「誰戳了你」。本機示範模式裡，示範好友每天會來戳你一次。

## 兩種模式

### 本機示範模式（預設）

`js/config.js` 還沒填 Supabase 設定時，App 會以示範模式運作：

- 帳號、好友與「雲端」都模擬在這台裝置的瀏覽器裡，打開網站就能直接體驗。
- 附有五位示範好友（`@momo_draws`、`@ashu_sketch`、`@lin_doodle`、`@nana_paint`、`@kai_ink`），每天都會「畫」一張新的圖。
- 規則和雲端版一樣：好友只看得到今天的，過了午夜就從「雲端」移除。
- 加了示範好友之後，過幾秒他們會在你今天的畫上留一句話；你也可以在好友的畫上留言。

### 雲端模式（讓朋友真正互相分享）

需要一個免費的 [Supabase](https://supabase.com) 專案（帳號、好友名單、今天的畫都存在這裡）。

1. **建立專案**：到 supabase.com 註冊，New project（免費方案即可，地區可以選 Tokyo 或 Singapore）。
2. **建立資料表**：左側 **SQL Editor** → New query → 把 [`supabase/schema.sql`](supabase/schema.sql) 的內容整份貼上 → **Run**。
   - 看到 `pg_cron 尚未啟用` 的提示也沒關係。想要自動排程清除的話，到 **Integrations → Cron** 開啟後再執行一次即可。
3. **關閉 Confirm email（必要）**：**Authentication → Sign In / Providers → Email**，把 **Confirm email** 關掉 → Save。
   - 註冊**不需要信箱**，只要「使用者 ID＋密碼」。App 會在背後用使用者 ID 組出一個收不到信的內部帳號（`使用者ID@users.art-day.invalid`，`.invalid` 是保留網域，不會寄出任何信）。
   - 如果忘了關，註冊時會出現「請關閉 Confirm email」的提示。關掉之前註冊失敗的帳號，可以到 **Authentication → Users** 刪除，那個使用者 ID 就能重新使用。
   - 建議到 **Authentication → Rate Limits** 確認註冊頻率有上限，避免有人用程式大量註冊。
4. **填入金鑰**：**Project Settings → API Keys**，複製 **Project URL** 和 **publishable key**（`sb_publishable_...`，舊版叫 anon public key），填進 [`js/config.js`](js/config.js)：

   ```js
   export const SUPABASE_URL = 'https://xxxxxxxx.supabase.co';   // 不要加 /rest/v1/
   export const SUPABASE_ANON_KEY = 'sb_publishable_...';
   ```

   publishable key 本來就設計成放在前端公開（任何人打開網站都看得到，藏不起來），資料安全由 `schema.sql` 裡的 Row Level Security 規則保護：
   - 只有登入的人能查看使用者 ID 與暱稱。
   - 只有**互相是好友**的人，才看得到彼此**今天**的畫與文字。
   - 每個人只能新增、刪除自己的畫。

   ⚠️ **secret key**（`sb_secret_...`，舊版叫 service_role key）和**資料庫密碼**絕對不要放進 repo，這個網站用不到它們。

5. **推上 GitHub**：commit 並 push 到 `main`，幾分鐘後網站就會更新。

### 忘記密碼

因為沒有綁定信箱，改用兩個「安全問題」讓使用者自己重設：

- **怎麼運作**：註冊後可以（選填、可跳過）回答「最喜歡的動物」（10 種冷門動物的選擇題）和「你是什麼國小畢業的」。之後也能到 **我的 → 忘記密碼的問題** 設定、修改或移除。忘記密碼時，在登入畫面按 **忘記密碼？**，輸入使用者 ID、答對兩題，就能設定新密碼並直接登入。學校名稱會先整理再比對（不分大小寫、全半形，忽略空白與標點，「臺」＝「台」，結尾的「國小／國民小學」可寫可不寫）。
- **答案是加密的**：資料庫只存 bcrypt 雜湊，連管理者都看不到答案；資料表沒有任何直接讀寫權限，只能透過 `supabase/schema.sql` 裡的函式存取。
- **次數限制**：同一個帳號 24 小時內答錯 5 次就會鎖住，之後不管答案對不對都要等 24 小時。重設成功後，舊的登入會被登出。
- **已經在使用雲端模式的話**：請把最新的 [`supabase/schema.sql`](supabase/schema.sql) 在 SQL Editor 整份再執行一次（可重複執行）。在那之前，「我的」裡這一區會自動隱藏，登入畫面按「忘記密碼？」會提示功能尚未開啟，其他功能不受影響。
- 示範模式有同樣的流程，資料只存在這台裝置。

**最後的手段**：沒設定問題、或被鎖住的人，可以請管理者在 Supabase 的 **SQL Editor** 幫忙重設（把 `某人的ID` 和 `新密碼` 換掉）：

```sql
update auth.users
   set encrypted_password = extensions.crypt('新密碼', extensions.gen_salt('bf'))
 where email = '某人的ID@users.art-day.invalid';
```

## 發佈到 GitHub Pages

這個專案是純靜態網站，不需要建置。第一次發佈時：

1. 到 GitHub repo 的 **Settings → Pages**。
2. **Source** 選 **Deploy from a branch**，Branch 選 **`main`**、資料夾 **`/ (root)`** → Save。
3. 等一兩分鐘，網站就會出現在 `https://dot7dot.github.io/Art-Day-Friends/`。

之後每次推到 `main` 都會自動更新。

## 在自己電腦上預覽

```bash
python3 -m http.server 8000
# 打開 http://localhost:8000
```

（需要用 http 伺服器開啟，直接雙擊 `index.html` 會因為瀏覽器安全限制無法載入模組。）

## 專案結構

```
index.html                 入口
css/style.css              樣式（白色系、淡橘線條、圓角平面）
js/config.js               ← Supabase 設定填這裡
js/app.js                  畫面與流程：好友（首頁）／日曆（上方月曆 + 下方當天內容，含今天）／我的
js/album.js                存到手機相簿（分享表／下載）、自動存、persist
sw.js                      service worker（網路優先、可安裝、離線外殼）
js/archive.js              本機日曆存檔（IndexedDB：畫、文字記錄、留言快取）
js/drawing-modal.js        畫作詳細頁：大圖與留言
js/imaging.js              圖片壓縮：本機版、雲端副本、縮圖
js/sketch.js               隨手畫畫板
js/backend-supabase.js     雲端模式
js/backend-local.js        本機示範模式
js/demo-art.js             示範好友的每日小畫
vendor/                    supabase-js（已打包成單一檔案，不依賴 CDN）
supabase/schema.sql        資料表、安全規則、自動清除
```
